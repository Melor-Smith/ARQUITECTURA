## Escenarios de calidad (formato ATAM)

Cada atributo se concreta en un escenario con sus seis partes (fuente, estímulo, artefacto, entorno, respuesta y medida). La medida dice cómo se comprueba: si hay una prueba automática, se cita; si no, se declara cómo se mediría.

| ID | Fuente | Estímulo | Artefacto | Entorno | Respuesta | Medida |
|---|---|---|---|---|---|---|
| AC-01 | Cajero | Emite una factura con ISC (sistemas 01, 02 y 03), ICBPER y líneas exoneradas | `Linea.calcular`, `Totales.de_lineas` | Operación normal | Calcula cada tributo con `Decimal` y redondeo a 2 decimales; los totales del JSON, del XML y del 14.1 coinciden | 0 diferencias en `test_tributos.py` y en los 7 XML aceptados por SUNAT beta (CDR 0 sin observaciones) |
| AC-02 | Cajero | Emite una factura completa | Caso de uso `EmitirComprobante` | Carga normal, OSE simulada | Emite sin degradar la respuesta | p95 < 500 ms en el proceso (`test_rendimiento.py`: p95 10,2 ms); la latencia de SUNAT se suma aparte |
| AC-03 | Atacante o error de un intermediario | Altera un byte del XML después de firmarlo | Firma XMLDSig | XML ya firmado, en tránsito | La OSE lo rechaza y el comprobante no queda aceptado | 100 % de alteraciones detectadas: código 2335 en la OSE simulada y en SUNAT beta (`test_firma_alterada_es_rechazo_2335`) |
| AC-04 | Dos cajas de la misma serie | Piden número al mismo tiempo | `SecuenciaCorrelativos` (memoria y SQLite) | 200 solicitudes concurrentes | Cada comprobante recibe un correlativo distinto; un 422 no consume número | 0 repetidos y 0 huecos (`test_concurrencia.py`, `test_rechazo_de_negocio_no_consume_correlativo`) |
| AC-05 | Cajero | Emite una factura con la OSE caída | Puerto `ClienteOSE` y estado `PENDIENTE_ENVIO` | Operación normal, sin respuesta de SUNAT | 202 `PENDIENTE_ENVIO`; reenvío con `POST …/envios` (503 + `Retry-After` mientras siga caída) | La venta termina en < 500 ms y 0 ventas perdidas: el comprobante firmado queda guardado (`TestOse`) |
| AC-06 | Desarrollador | Agrega un campo al DTO sin cambiar antes el contrato | `specs/contracts/` y `esquemas.py` | Integración continua | La CI falla y `scripts/exportar_openapi.py` dice qué difiere | 0 diferencias entre contrato y código para fusionar (`test_el_codigo_implementa_exactamente_el_contrato`) |
| AC-07 | Equipo de desarrollo | Cambia la persistencia de memoria a SQLite (o de la OSE simulada a SUNAT) | Puertos `Protocol` y `bootstrap.py` | Mantenimiento | Solo cambia un adaptador y la configuración; el dominio no se toca | 0 líneas cambiadas en `src/domain` y `src/application`; toda la suite de API pasa con ambos adaptadores (fixture `persistencia`) |
| AC-08 | Operador de despliegue | Arranca en producción sin definir `ABC_API_TOKENS` | `Configuracion.__post_init__` | Despliegue a producción | El servicio no arranca y explica qué variable falta | 0 arranques en producción con tokens `dev-*` (`test_configuracion.py`) |
| AC-09 | Auditor de SUNAT o docente | Pide dónde está un dato normativo en el XML, la API y el PLE | Matriz `matriz.yaml` | Revisión | La fila indica el XPath, el campo del contrato, el campo del PLE y la prueba | 72 filas, 0 sin ubicación verificada (`test_matriz.py`) |
| AC-10 | Jefe de almacén | Reprocesa el mismo archivo del sistema antiguo | `MigrarLoteLegado` | Migración por lotes | Las fichas repetidas quedan `DUPLICADA` y el Kardex no cambia | 0 movimientos duplicados y conciliación `cuadra = true` (`test_reprocesar_el_mismo_lote_es_seguro`) |
| AC-11 | Administrador de TI de la sucursal | Instala la API local en una caja Windows | MSI (PyInstaller + WiX) | Equipo Windows sin Python instalado | Se instala en silencio y la API responde en `127.0.0.1` | Instalación con `msiexec /qn` y `/salud` en 200, verificados en `windows-latest` (workflow `instalador-msi`) |
| AC-12 | Contador o SUNAT | Pide el XML y el CDR de una venta de hace meses | Persistencia SQLite en el volumen `/datos` | Después de reinicios y actualizaciones | Devuelve el XML firmado original y su CDR | El XML firmado y el CDR se recuperan tras reiniciar (`test_los_datos_sobreviven_a_un_reinicio_y_el_correlativo_continua`); el plazo legal completo exige además respaldo diario fuera del servidor (pendiente) |
